# API Testing — TeamSpace

This folder describes an API testing approach for the fictional TeamSpace application.

## Important limitation

TeamSpace is a fictional product. The endpoint paths and request/response examples in this portfolio are illustrative contract examples, not working live endpoints. Do not send requests to them expecting a real service.

## What this section demonstrates

- HTTP method selection
- Status-code validation
- Response-body and schema checks
- Required-field and invalid-input tests
- Authentication and authorization checks
- Data-integrity verification
- Safe handling of test credentials

## Suggested hands-on practice

To turn this plan into executed evidence:

1. Choose a public demo API or a small local sample API you are allowed to test.
2. Read its documentation and identify the actual supported endpoints.
3. Create a Postman collection using the real documented endpoints.
4. Add assertions based on the API's documented behavior.
5. Run the collection and save sanitized results.
6. Update this repository to identify the API used, the test date, and the actual outcomes.

Do not claim that illustrative scenarios passed until they have been run against a real, permitted test target.
